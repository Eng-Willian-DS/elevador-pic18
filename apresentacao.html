Config Bits + init_hardware()

Juliano · Slide 5 
#pragma config FOSC   = HS         // cristal 20 MHz
#pragma config CPUDIV = OSC1_PLL2  // CPU = Fosc sem PLL
#pragma config WDT    = OFF        // watchdog off
#pragma config PBADEN = OFF        // PORTB digital
#pragma config LVP    = OFF        // sem LVP
void init_hardware(void) {
    ADCON1 = 0x0F;  // PCFG=1111: tudo digital
                    // (AN0 reabilitado em init_adc)
    TRISB  = 0xFF;  // RB0-RB5 = entradas
    INTCON2bits.RBPU = 0; // pull-ups ON

    TRISDbits.TRISD0 = 0; // motor IN1
    TRISDbits.TRISD1 = 0; // motor IN2
    TRISDbits.TRISD2 = 0; // LED porta
    LATD = 0x00;

    TRISCbits.TRISC2 = 0; // RC2 = PWM
    TRISAbits.TRISA0 = 1; // RA0 = ADC
}

Por que FOSC = HS + CPUDIV?

  • FOSC = HS — seleciona a fonte: cristal externo 20 MHz em modo alta velocidade
  • CPUDIV = OSC1_PLL2 — garante que o CPU use o oscilador direto (20 MHz), sem divisão pelo PLL
  • Sem CPUDIV explícito, o CPU poderia rodar em 10 ou 5 MHz e quebrar todos os cálculos de tempo

Por que ADCON1 = 0x0F primeiro?

  • PCFG = 1111 desabilita todos os analógicos
  • Reset padrão deixa PORTB parcialmente analógico — leitura dos botões falharia
  • AN0 é reabilitado depois em init_adc()

PWM — 7 kHz e 38% Duty Cycle

Juliano · Slide 6
Fpwm =Fosc ÷ (4 × Prescaler × (PR2 + 1))= 20M ÷ (4×4×179) = 6.983 Hz ≈ 7 kHz ✓
DC10bit =int( 0,38 × 4 × (PR2 + 1) )= int( 0,38 × 716 ) = 272
CCPR1L =DC10bit >> 2= 272 >> 2 = 68
DC1B =DC10bit & 0x03= 272 & 3 = 0 → CCP1CON = 0x0C
Duty real =272 ÷ 716= 37,99% ≈ 38% ✓
void init_pwm(void) {
    OpenTimer2(TIMER_INT_OFF & T2_PS_1_4 & T2_POST_1_1); // prescaler 1:4
    OpenPWM1(178);    // PR2 = 178  →  Fpwm ≈ 7 kHz
    SetDCPWM1(0);     // inicia desligado
}
// Ligar motor (38%): SetDCPWM1(272);   |   Desligar: SetDCPWM1(0);

Timer0 — Base de Tempo de 1 ms

Willian · Slide 7
Fosc = 20 MHzT_maq = 4 ÷ 20 MHz = 200 ns
Prescaler 1:8T_tick = 8 × 200 ns = 1,6 µs por tick
Para 1 ms:1.000 µs ÷ 1,6 µs = 625 ticks
Recarga:65.536 − 625 = 64.911 = 0xFD8F
// ISR — endereço 0x0008
#pragma code int_alta = 0x0008
void int_alta(void) { _asm GOTO ISR_T0 _endasm }
#pragma code

#pragma interrupt ISR_T0
void ISR_T0(void) {
    ms_tick++;          // +1 a cada 1 ms
    TMR0H = 0xFD;       // recarga preload
    TMR0L = 0x8F;
    INTCONbits.TMR0IF = 0;
}

ISR — o que é?

Função executada automaticamente quando o Timer0 estoura. O programa principal para, a ISR roda (incrementa ms_tick), e o programa volta exatamente de onde parou. Dura microsegundos.

ms_tick na prática

  • Contador global incrementado pela ISR a cada 1 ms
  • (ms_tick - t_inativo) >= 2300 = "passaram 2,3 s"
  • (ms_tick - t_viagem) >= 3000 = "andou 1 andar"
  • Todas as contagens simultâneas — sem bloquear o loop

ADC — Potenciômetro Simulando Temperatura

Karoline · Slide 8 
void init_adc(void) {
    // Tensão ref: VDD/VSS (VCFG = 00)
    // PCFG = 1110: somente AN0 analógico
    ADCON1 = 0x8E; // ADFM=1 (bit7) + PCFG=1110
    //  ↑ PICSimLab usa PIC18F452:
    //    ADCON2 não existe — ADFM fica em ADCON1[7]

    ADCON0 = 0x01; // AN0 selecionado + ADON=1
}

unsigned int ler_adc(void) {
    ADCON0 |= 0x04; // GO = bit2 (PIC18F452)
    //  ↑ No PIC18F4550 seria bit1, mas no simulador é bit2
    Delay10KTCYx(1);  // ~2 ms (ADIF não funciona no sim.)
    return ((unsigned int)ADRESH << 8) | ADRESL;
}

Mapeamento → temperatura

  • ADC 10 bits: 0 a 1023 (0 V a 5 V)
  • temp = adc × 50 / 1023 → graus inteiros
  • temp_10 = adc × 500 / 1023 → décimos de grau
  • Ex: adc = 640 → temp_10 = 312 → 31,2 °C
  • Limiar STOP: 31 °C → adc ≈ 634

Por que sem float?

  • C18 LITE tem limitações com ponto flutuante
  • Usar unsigned long evita overflow de 16 bits nas multiplicações
  • temp_10 / 10 = parte inteira · temp_10 % 10 = decimal

CGRAM — Criando os Símbolos ↑ e ↓

Ana Caroline · Slide 10

HD44780 suporta até 8 chars customizados de 5×8 pixels na CGRAM. Cada char = 8 bytes onde os 5 bits menos significativos definem os pixels.

↑ char 0 — slot 0x40
↓ char 1 — slot 0x48
Exibir: lcd_escreve_dado(0x00) = ↑ · lcd_escreve_dado(0x01) = ↓
const unsigned char CIMA[8]  =
    {0x04,0x0E,0x1F,0x04,0x04,0x04,0x04,0x00};
const unsigned char BAIXO[8] =
    {0x04,0x04,0x04,0x04,0x1F,0x0E,0x04,0x00};

void carregar_chars(void) {
    unsigned char i;
    // aponta cursor para char 0 na CGRAM
    lcd_envia_controle(0, 0, 0x40, 45);
    for (i=0; i<8; i++) lcd_escreve_dado(CIMA[i]);

    // aponta para char 1
    lcd_envia_controle(0, 0, 0x48, 45);
    for (i=0; i<8; i++) lcd_escreve_dado(BAIXO[i]);

    // volta cursor para DDRAM (tela)
    lcd_posicao(1, 1);
}

Botões — ler_botoes() com Debounce 20 ms

Ana Caroline · Slide 11 
static unsigned long t_deb[7] = {0};

void ler_botoes(void) {
    unsigned char i, portb;
    portb = PORTB; // snapshot do porto inteiro

    for (i = 1; i <= TOTAL_ANDARES; i++) {
        // pull-up ativo: botão LOW = pressionado
        if (!(portb & (1 << (i-1)))) {
            // debounce: só aceita após 20 ms
            if ((ms_tick - t_deb[i]) >= 20) {
                t_deb[i] = ms_tick;
                if (i != (unsigned char)andar_atual) {
                    fila[i]   = 1;
                    t_inativo = ms_tick;
                }
            }
        }
    }
}

O que é bouncing?

Contato mecânico oscila 5–20 ms ao ser pressionado. Sem tratamento, 1 toque = vários acionamentos.

Solução: debounce por tempo

  • t_deb[i] = timestamp do último toque aceito por andar
  • Aceita novo toque só se (ms_tick − t_deb[i]) ≥ 20
  • Lemos PORTB inteiro de uma vez (snapshot consistente)
  • Lógica invertida: bit = 0 → botão ativo (pull-up)

Máquina de Estados — Visão Geral

Ana Caroline · Slide 12
IDLE

Motor parado · aguarda botão ou timeout de 2,3 s · verifica temp

MOVENDO

Motor ligado · avança 1 andar a cada 3 s via ms_tick · algoritmo SCAN

RETORNANDO

Igual MOVENDO · destino fixo = 3º andar · disparado por inatividade

PORTA_ABERTA

Motor parado · 4 fases de 1 s · LED apaga aos 2 s (fechando)

SUPERAQUECIDO

Motor para imediatamente · temp > 31 °C · retoma viagem ao normalizar

Loop principal: ler_adc() → ler_botoes() → maquina_estados() → atualizar_lcd()
Qualquer estado de movimento: se temp > 31 °C → SUPERAQUECIDO instantâneo

void motor_liga(void) {
    if (direcao == SUBINDO)
        { MOTOR_IN1=1; MOTOR_IN2=0; }

        { MOTOR_IN1=0; MOTOR_IN2=1; }

atualizar_lcd() — Display em Tempo Real

Erick · Slide 15 
void atualizar_lcd(void) {
    char buf[18];
    // temperatura sem float
    unsigned int temp_10 =
        (unsigned int)((unsigned long)adc_raw
                        * 500UL / 1023UL);

    // ── Linha 1: "Andar: X  [dir]" ──
    lcd_posicao(1, 1);
    sprintf(buf, "Andar: %d  ", andar_atual);
    imprime_buffer_lcd(buf, 10); // 10 chars

    if (estado == SUPERAQUECIDO)
        imprime_string_lcd("STOP  ");
    else if (direcao == SUBINDO)
        { lcd_escreve_dado(0x00);        // ↑ CGRAM
          imprime_string_lcd("     "); }
    else if (direcao == DESCENDO)
        { lcd_escreve_dado(0x01);        // ↓ CGRAM
          imprime_string_lcd("     "); }
    else imprime_string_lcd("      ");

    // ── Linha 2: "Tmp: XX.X C" ──
    lcd_posicao(2, 1);
    sprintf(buf, "Tmp: %u.%uC       ",
            temp_10/10, temp_10%10);
    imprime_buffer_lcd(buf, 16); // 16 chars fixos
}

Por que 16 chars fixos?

O LCD não apaga sozinho — espaços de preenchimento sobrescrevem caracteres anteriores. Sem isso, "STOP" deixaria restos de "↑" na tela.
